# TestFlight (베타 배포)

> **누가 봄**: DevOps, FE
> **언제 봄**: 친구/베타 테스터에게 공유, App Store 제출 전 검증
> **함께 봐야 할 문서**: [`배포.md`](배포.md), [`보안.md`](보안.md)

## TestFlight이 뭐야

Apple 공식 베타 배포 채널.
- 최대 **10,000명** 외부 테스터에게 .ipa 배포
- 7일 만료 없음 (빌드당 최대 90일 유효)
- 사용자는 TestFlight 앱에서 설치 — Mac 케이블 연결 불필요
- App Store Connect 대시보드에서 크래시/피드백 수집

## 1회 셋업 (최초 한 번)

### 1. App Store Connect에 앱 등록
[App Store Connect](https://appstoreconnect.apple.com) → My Apps → "+" → New App.

| 필드 | 값 |
|------|-----|
| Platform | iOS |
| Name | 오타쿠피드 (또는 OtakuFeed) |
| Primary Language | Korean |
| Bundle ID | `com.giwon.otakufeed` (드롭다운에서 선택, 없으면 [Identifiers](https://developer.apple.com/account/resources/identifiers/list)에서 등록 후 새로고침) |
| SKU | 임의 (예: `otakufeed-001`) |

→ 등록 끝. 아직 metadata는 비어있어도 됨 (TestFlight는 이메일/스크린샷 없이 가능).

### 2. EAS와 App Store Connect 연결
```bash
cd /Volumes/Dev/Playground/otaku-feed
npx eas credentials
```
선택:
- Platform: **iOS**
- Profile: **production**
- "Apple ID에 sign in" → 2FA 통과
- 자동으로 distribution cert + provisioning profile 생성

## 일상 베타 배포 (매번)

### 1. 빌드 (preview 프로필)
```bash
npm run build:preview
# 또는: npx eas build --platform ios --profile preview
```
⏱ ~15-20분 클라우드 빌드. 진행: `https://expo.dev/accounts/<user>/projects/otaku-feed/builds`

### 2. TestFlight에 업로드
```bash
npx eas submit --platform ios --latest
```
⏱ ~5분. App Store Connect → TestFlight 탭에 자동 등록.

### 3. 베타 테스터 추가
App Store Connect → 우리 앱 → **TestFlight** 탭:

**A. 내부 테스터 (즉시, 최대 100명)**
- "Internal Testing" 그룹 생성
- App Store Connect 사용자 추가 (Apple ID 이메일)
- **Apple 심사 없음** — 즉시 알림 가서 설치 가능

**B. 외부 테스터 (최대 10,000명)**
- "External Testing" 그룹 생성
- 이메일로 추가 (App Store Connect 계정 없어도 OK)
- 첫 빌드는 **Apple Beta App Review** 통과 필요 (~1일)
- 그 후 빌드는 즉시 배포

### 4. 테스터의 설치 흐름
1. 이메일로 TestFlight 초대 받음
2. App Store에서 **TestFlight** 앱 설치 (1회)
3. 초대 링크 탭 → "Accept" → "Install"
4. OtakuFeed 설치됨 (TestFlight 아이콘 작게 옆에 붙음)
5. 만료까지 90일, 재설치 무한

## 빌드 만료 / 재배포

- TestFlight 빌드는 **업로드 후 90일** 후 만료
- 만료되면 새 빌드 (`npm run build:preview` + `eas submit`) 후 테스터에게 자동 알림
- 옛 빌드는 자동 비활성화

## 자주 헷갈리는 것

### TestFlight vs Direct .ipa
- **TestFlight**: Apple 인프라, 알림 자동, 90일 유효, 외부 테스터는 첫 빌드 심사
- **Direct .ipa (EAS preview internal)**: QR 코드 install, UDID 등록된 폰만, 1년 유효, 심사 없음

→ 친구 1-2명은 Direct 가 빠름. 5명 이상은 TestFlight가 편함.

### 앱 아이콘이 회색
빌드 직후 처음엔 회색 아이콘. 잠시 후 자동으로 정상 컬러. 안 바뀌면 폰 재시작.

### "App is not available" 에러
- 베타 만료
- 또는 TestFlight 그룹에서 빌드 비활성화
→ App Store Connect에서 그룹 → 빌드 활성화 확인

### 외부 테스터 첫 빌드 심사 거절
- **Privacy 항목 누락**: App Store Connect → 우리 앱 → "App Privacy"에서 데이터 수집 여부 답변 필요 (한 번만)
- **Crash on launch**: 빌드 자체가 켜지면 죽는 경우. 로컬에서 release 빌드로 재현 후 fix
- **Beta App Description 누락**: TestFlight 그룹의 "Test Information" 채우기 (한국어 OK)

## 비용 / 한도

- 무료 (Apple Developer $99/년에 포함)
- 동시 활성 빌드 1개/플랫폼 (옛 빌드 자동 만료)
- 외부 테스터 최대 10,000명

## TestFlight Connect API (선택)

자동화 빌드 → 자동 TestFlight 업로드를 GitHub Actions에서:
- `eas submit --platform ios --latest --non-interactive`
- 필요한 환경변수: EAS robot token, App Store Connect API key

도입 시 별도 가이드 작성.

## 다음 단계 — App Store 정식 제출
