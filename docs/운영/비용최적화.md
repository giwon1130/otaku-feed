# 비용 최적화

> **누가 봄**: DevOps, FE, BE
> **언제 봄**: 비용 알림, 분기별 점검, 대규모 사용자 증가 전
> **함께 봐야 할 문서**: 백엔드 [`docs/운영/비용최적화.md`](https://github.com/giwon1130/otaku-feed-api/blob/main/docs/운영/비용최적화.md)

## 적용된 절감 작업

### 클라이언트
1. **`apiHealth` keepalive 조건부** — 비로그인은 백엔드 호출 0 → Railway 비용 0
2. **`useBackendHealth` enabled gating** — 비로그인 polling 안 함, 30s → 60s
3. **`apiMe` 1시간 AsyncStorage 캐시** — 부팅마다 호출 안 함
4. **`loadPrefs`/`loadSwipes` 5분 TTL** — UI refresh마다 서버 안 때림
5. **`flushPending` swipe 배치 푸시** — 빠른 5 swipe = 5 RPC → 1 bulk RPC
6. **AniList 동시성 5개 큐** — 429 회피
7. **AniList SWR + 2-tier 캐시** — 부팅 즉시 화면 + AniList 호출 감소
8. **번역 배치 + 회로 차단** — DeepL 호출 감소 + 한도 보호

### 백엔드
9. **gzip 응답 압축** — 응답 50–80% 감소 → egress 절감
10. **`SwipeResponse` id 제거** — 응답 row당 ~40B 절감
11. **`POST /swipes/bulk`** — 클라 배치와 짝, batchUpdate 단일 RTT
12. **HikariCP** — `DriverManager` → 풀링으로 connection 재사용 (CPU/메모리 절감)
13. **`spring.main.lazy-initialization: true`** — 부트 시간 단축, cold start 회복 빠름
14. **Postgres 정렬 인덱스** — `(user_id, swiped_at DESC)` — sort 비용 일정

## 비용 측정 효과 (예상)

| 시나리오 | 작업 전 | 현재 |
|---|---|---|
| 비로그인 사용자 1시간 활성 | health 120 + keepalive 1 = **121 호출** | **0 호출** |
| 로그인 사용자 1시간 (캐시 hit) | me 1 + health 120 = **121 호출** | health 60 = **60 호출** |
| 로그인 + HomeTab refresh 5번 | prefs 5 + swipes 5 = **10 호출** | TTL 안이면 **0 호출** |
| 빠른 swipe 20번 | swipe POST **20** | bulk 1회 = **1 호출** |
| `/swipes` 응답 (100 row) | full + raw | gzip + id 제거 = **~30%** |
| Railway egress 전체 | baseline | **약 60–70% 감소** 예상 |

## 모니터링 (현재)

- Railway 대시보드: RAM/CPU/Network/Storage 그래프
- DeepL 사용량: `getDeeplQuota()` (앱 내), 80% 도달 시 경고 플래그
- AniList: 429 발생 시 toast로 알림 (간접 모니터링)

## 추가 절감 옵션 (필요 시)

### 클라이언트
- **HomeTab fresh path translate 묶기** — 각 섹션별 번역 → 1 batch
- **prefetch on viewability** — 사용자가 보기 직전에 미리 fetch
- **이미지 캐시 size 제한** — RN 기본 외 명시 제어 (현재 RAM 위험 감수)

### 백엔드
- **Postgres connection pooler (PgBouncer)** — Railway add-on
- **Backend cache (Caffeine)** — `/prefs`/`/swipes` 사용자별 메모리 캐시
- **CDN/Cloudflare** — `/health` edge 캐시 (Railway 호출 0)

### 인프라
- **Railway Pro 전환** — 항상 깨어있음 (cold start 0). $20/월 + 사용량
- **Postgres dedicated DB로 분리** — 작은 인스턴스로 다운사이징
- **EAS 빌드** — Apple Dev $99/년이 7일 만료 회피보다 저렴 (개발 시간 비용 고려)

## 결정 기준

**언제 다음 단계로 가나**:
- 무료 한도 50% 도달 → 알림
- 80% 도달 → 절감 작업 시작
- 100% 도달 → 유료 전환 또는 대체 서비스

**비용 vs 시간**:
- 개발 시간 시급 환산: $30/시간 가정
- 절감 작업 1시간으로 월 $1 줄어들면 30개월 ROI = 매력 없음
- 50% 이상 줄어들거나 점증 비용 막는 작업만 우선
