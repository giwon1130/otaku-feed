# 보안

> **누가 봄**: DevOps, FE
> **언제 봄**: 신규 인증 추가, 감사, 사고 후 재점검
> **함께 봐야 할 문서**: 백엔드 [`docs/운영/보안.md`](https://github.com/giwon1130/otaku-feed-api/blob/main/docs/운영/보안.md)

## 인증

### JWT
- **저장 위치**: `expo-secure-store` (iOS Keychain / Android Keystore)
- **키**: `otaku_jwt` (콜론 비허용 → 옛 `otaku:jwt`는 첫 `getToken`에서 자동 마이그레이션)
- **만료**: 30일 (`expiration-hours: 720`)
- **재발급**: 만료되면 사용자가 재로그인 (자동 refresh token 미지원)
- **회전**: `JWT_SECRET` 변경 시 모든 사용자 즉시 로그아웃 ([환경변수.md](환경변수.md) "키 회전" 참고)

### SSO
- **카카오**: `@react-native-kakao/user` — `app.json` plugins에 등록
- **구글**: `@react-native-google-signin/google-signin` — iOS Url Scheme 등록 필요
- **무방해 인증 흐름** — Expo Go에선 동작 X. dev client 풀빌드 필수

### 비밀번호 (백엔드)
- BCrypt 해시 저장 (백엔드 ADR 참고)
- 클라엔 평문으로 전송 (HTTPS 의존)
- 비밀번호 검증 정책 (최소 길이 등) — 백엔드 책임

## 통신

- 모든 외부/백엔드 호출은 **HTTPS only**
- `EXPO_PUBLIC_API_URL`이 https인지 확인 (배포 시)
- Certificate pinning 미적용 (필요해지면 검토)

## 권한 (Permissions)

### iOS Info.plist (현재 설정)
- 카카오/구글 SSO를 위한 URL Scheme
- 추가 권한 (위치/사진 등) 사용 안 함

### 새 권한 추가 시
- `app.json` 또는 `Info.plist` 직접 편집
- App Store 심사 시 사용 목적 명시 필요 (NSLocation* 등)

## 데이터

### 로컬 (AsyncStorage)
- 평문 저장. **민감하지 않은 것만**:
  - 좋아요/패스 기록
  - 검색 히스토리
  - 취향 (장르)
  - 캐시 (anime, swr, translation)
- 민감한 것 (JWT)은 SecureStore

### 서버 전송
- 좋아요/패스/취향 → JWT 인증 + HTTPS
- 비밀번호는 로그인 시 한 번만, 평문 송신 (HTTPS 보호)

### 사용자가 지울 권리
- 로그아웃 → `clearLocalUserData` (swipes/검색기록/취향 정리)
- 계정 삭제 — 미구현. 백엔드에 user delete endpoint 필요

## CORS (백엔드)

`OTAKU_CORS_ALLOWED_ORIGINS=*` (모바일 앱이라 origin 의미 X). 웹 클라이언트 도입 시 명시 origin으로 변경.

## Rate Limit

- AniList: 클라 측 동시성 5개 큐 (서버 측 추가 보호 X)
- 백엔드: 명시적 rate limit 없음 (호출량 자체가 작음)

## 안티-남용

- ❌ 기능적 안티-남용 (가짜 계정 방지) 없음 — 친구/가족 위주 사용 가정
- 향후 검토: hCaptcha (회원가입), IP 기반 throttle

## 비밀 관리

### 클라이언트
- `.env` gitignored
- `EXPO_PUBLIC_*` 키는 번들에 들어감 → 진짜 비밀 X (DeepL Free 키는 사용량 한도라 비교적 안전)

### 백엔드
- Railway 환경변수 (UI에서 설정, 노출 안 됨)
- `JWT_SECRET`, `KAKAO_OAUTH_CLIENT_SECRET` 등은 절대 코드 X
- `git secret scan` 도입 (TODO)

## 감사 / 점검 체크리스트

- [ ] `.env`가 gitignore에 있는가
- [ ] 새 native 권한 추가 시 사용 목적 주석
- [ ] OAuth Client ID/Secret이 코드에 hardcoded 안 됨
- [ ] JWT 만료 동작 확인 (30일 후 재로그인 유도)
- [ ] HTTPS 연결만 사용
- [ ] 사용자 데이터 삭제 요청 처리 가능 (계정 삭제 endpoint)
- [ ] 백엔드 BCrypt round 적절 (10+)

## 알려진 약점

- **Refresh token 미구현** — 30일 만료 후 강제 재로그인
- **계정 삭제 endpoint 없음** — GDPR 등 대응 안 됨
- **백엔드 rate limit 없음** — DOS 노출
- **로깅에서 PII 마스킹 미적용** — 이메일이 그대로 로그에 찍힐 수 있음 (Sentry 도입 시 PII 필터)
