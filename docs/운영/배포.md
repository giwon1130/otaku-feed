## 첫 배포 (새 폰)

### 1. 폰 준비
- **개발자 모드 켜기**: 설정 → 개인정보 보호 및 보안 → 개발자 모드 ON → 재시작
- **Mac에 케이블 연결** → "이 컴퓨터를 신뢰" 허용
- **Apple ID 로그인** (Mac/Xcode 동일 계정 권장)

### 2. UDID 확인
```bash
xcrun xctrace list devices
```
실제 UDID는 `xctrace` 형식 사용 (예: `00008150-...`). `devicectl` 출력 UDID는 expo가 못 잡는 경우 있음.

### 3. 빌드
```bash
cd /Volumes/Dev/Playground/otaku-feed
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 \
  npx expo run:ios --device "<UDID>" --port 8082
```

⚠️ `LANG=en_US.UTF-8` 필수 (CocoaPods Encoding::CompatibilityError 방어)

⚠️ Port 8082 (8081은 다른 프로젝트 사용 중)

⏱ 첫 빌드 10–15분 (RN core source 컴파일 포함). 두 번째부터 ccache로 빠름.

### 4. 첫 빌드 알려진 이슈
Xcode 26 + Expo 54 + reanimated 4 + kakao 조합에서 3가지 에러 만남:
1. `cannot link directly with 'SwiftUICore'` → deployment target 18.0
2. `Undefined symbol: facebook::react::Sealable::Sealable()` → `buildReactNativeFromSource: true`
3. `fmt` consteval → fmt만 c++17

**이 레포엔 패치 적용됨** (Podfile + Podfile.properties.json + project.pbxproj). 이미 `pod install` → `expo run:ios`만 하면 됨. 패치 자세한 내용은 AGENTS.md "iOS 풀 빌드 알려진 이슈" 참고.

## EAS Build

Apple Developer Program 가입됨 → EAS 빌드 활성화.

### 셋업 (한 번만)

```bash
cd /Volumes/Dev/Playground/otaku-feed
# eas-cli는 devDep로 설치돼있음
npx eas login                          # Expo 계정 로그인
npx eas init                           # projectId 발급 → app.json.extra.eas.projectId 자동
npx eas credentials                    # iOS distribution cert 등록 (Apple ID 로그인 필요)
```

### 프로필 (eas.json)

| 프로필 | 용도 | 배포 |
|------|------|------|
| `development` | 개발용 dev client. JS는 Metro에서 받음 | internal (UDID 등록 폰) |
| `preview` | 내부 테스트. 풀 빌드 .ipa | internal (TestFlight 또는 ad-hoc) |
| `production` | App Store 제출용 | App Store |

### 빌드 명령

```bash
# 개발용 dev client (한 번 만들면 7일 만료 없이 1년)
npx eas build --platform ios --profile development

# 내부 테스트 .ipa (TestFlight 업로드 가능)
npx eas build --platform ios --profile preview

# 앱스토어 제출용
npx eas build --platform ios --profile production
```

⏱ 클라우드 빌드 ~15–20분. 진행 상황은 `https://expo.dev/accounts/<user>/projects/otaku-feed/builds`에서 확인.

### 폰에 설치

빌드 끝나면:
- **TestFlight** (preview/production) — Apple ID 추가 후 TestFlight 앱에서 설치
- **Direct install (preview)** — EAS가 주는 QR 코드 → 폰 카메라 스캔 → 설치 페이지

### Submit (App Store 제출)

```bash
npx eas submit --platform ios --profile production --latest
```

App Store Connect에 자동 업로드. 그 후 App Store Connect 대시보드에서 metadata/screenshots 입력 → "Submit for Review".

### 로컬 빌드 (대안)

EAS 클라우드 안 쓰고 로컬에서 `expo run:ios`도 여전히 가능. 단, 7일 무료 provisioning profile만 가능.

→ EAS 도입 후엔 `expo run:ios`는 빠른 디버깅용, EAS는 배포용으로 역할 분리.

### 환경변수 / Secrets

EAS 빌드 환경엔 .env가 자동으로 안 들어감. 필요하면:

```bash
# secret 등록 (한 번)
npx eas secret:create --scope project --name EXPO_PUBLIC_API_URL --value 'https://...'
```

또는 `eas.json`의 `env` 필드에 빌드 프로필별로 명시.

### 버전 관리

`app.json`:
- `version: "1.0.0"` — 사용자에게 보이는 마케팅 버전
- `ios.buildNumber: "1"` — Apple 내부 빌드 번호 (eas.json `autoIncrement: "buildNumber"`로 자동 +1)

새 release 시 `version` 수동 bump (1.0.0 → 1.0.1).

### 알려진 함정

- **첫 `eas build`엔 cert 등록 필요** — Apple ID 2FA 통과 필요 (브라우저 떠서 인증)
- **빌드 큐 대기** — 무료 plan 시 우선순위 낮음. 빠르게 받으려면 EAS Production plan
- **번들ID 충돌** — App Store에 같은 bundleId 등록되면 새로 만들기 불가 (다른 ID 쓰거나 Apple Developer 콘솔에서 정리)
