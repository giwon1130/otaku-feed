# 데이터 모델

> **누가 봄**: FE, BE
> **언제 봄**: 새 필드 추가 시 (BE↔FE 1:1 확인), 새 도메인 타입 만들 때
> **단일 진실의 원천**: `src/types.ts` (FE), [otaku-feed-api](https://github.com/giwon1130/otaku-feed-api) Domain (BE).
> 백엔드 schema는 [otaku-feed-api/docs/엔지니어링/데이터모델.md](https://github.com/giwon1130/otaku-feed-api/blob/main/docs/엔지니어링/데이터모델.md) 참고.

## 핵심 타입

### `Anime`
앱 전체에서 가장 자주 쓰는 도메인 객체. AniList Media를 mapping한 것.

```ts
type Anime = {
  id: number              // AniList Media id
  title: string           // 한국 출시명 우선 (synonyms) → 영어 → romaji
  titleNative: string     // 일본어 원제
  coverImage: string      // extraLarge → large
  bannerImage: string | null
  score: number           // 0–100
  episodes: number | null // 미정이면 null
  status: AnimeStatus
  season: AnimeSeason | null
  seasonYear: number | null
  genres: string[]        // 영어 (GENRE_KO로 한국어 변환)
  description: string     // HTML strip 됨
  studios: string[]       // isMain만
  popularity: number
  source: string          // MANGA / LIGHT_NOVEL / ORIGINAL ...
}
```

### `AnimeStatus`
```ts
type AnimeStatus = 'FINISHED' | 'RELEASING' | 'NOT_YET_RELEASED' | 'CANCELLED' | 'HIATUS'
```

### `AnimeSeason`
```ts
type AnimeSeason = 'WINTER' | 'SPRING' | 'SUMMER' | 'FALL'
```

### `SwipeRecord`
사용자의 좋아요/패스 기록.

```ts
type SwipeResult = 'like' | 'dislike' | 'skip'  // skip은 미사용
type SwipeRecord = {
  animeId: number
  result: SwipeResult
  swipedAt: string  // ISO 8601
}
```

### `UserPrefs`
온보딩 결과 + 좋아하는 장르.

```ts
type UserPrefs = {
  favoriteGenres: string[]      // 영어 (Action, Romance, ...)
  onboardingDone: boolean       // 장르 선택 완료
  tasteOnboardingDone?: boolean // 취향 분석 완료 (디바이스 로컬 only)
}
```

**주의**: `tasteOnboardingDone`은 서버 동기화 안 함 (디바이스 로컬 플래그). 새 디바이스에선 다시 거치게.

### `SeriesEntry`
디테일 모달의 시리즈 보는 순서 카드.

```ts
type RelationType =
  'PARENT' | 'PREQUEL' | 'SEQUEL' | 'SIDE_STORY'
  | 'SPIN_OFF' | 'ALTERNATIVE' | 'SUMMARY'
  | 'ADAPTATION' | 'SOURCE' | 'OTHER'

type SeriesEntry = {
  id: number
  title: string
  titleNative: string
  coverImage: string
  format: string | null   // TV / OVA / MOVIE / SPECIAL
  episodes: number | null
  seasonYear: number | null
  season: AnimeSeason | null
  score: number
  status: AnimeStatus
  relationType: RelationType
}
```

### `ExternalLink`
디테일 모달의 "어디서 봐?" 섹션.

```ts
type ExternalLink = {
  url: string
  site: string             // 'Laftel', 'Netflix', 'Disney+' ...
  type: 'STREAMING' | string
  color: string | null
  regional?: boolean       // true=한국 전용(라프텔 등), false/undefined=글로벌
}
```

### `TabKey`
```ts
type TabKey = 'home' | 'explore' | 'swipe' | 'mylist'
```

## AniList raw shape

`src/api/anilist/mappers.ts`의 `RawMedia` 타입과 매핑됨. mapAnime이 raw → Anime 변환.

슬림/풀 fragment 차이:
- `ANIME_FIELDS_LIST`: id/title/synonyms/coverImage/score/episodes/status/season/seasonYear/genres/popularity
- `ANIME_FIELDS`: 위 + bannerImage/description/studios/source

`RawMedia`는 두 fragment 모두 수용 가능하게 옵셔널 필드 사용.

## 백엔드 응답 매핑

| 백엔드 DTO | 클라이언트 타입 |
|-----------|-----------------|
| `SwipeResponse { animeId, result, swipedAt }` | `SwipeRecord` (id 필드 제거됨, 슬림화 ADR-009) |
| `PrefsResponse { favoriteGenres }` | `UserPrefs.favoriteGenres` (다른 필드는 로컬에서 합성) |
| `AuthResponse { token, userId, email, nickname }` | App.tsx의 `user: AuthResponse` |
| `BulkSwipeRequest { swipes: [{animeId, result}] }` | `flushPending`이 큐에서 빌드 |

## 캐시 키 규칙

| Prefix | 의미 | 위치 |
|--------|-----|-----|
| `swr2:` | SWR 캐시 (raw English Anime) | `api/anilist/swr.ts` |
| `tl4:` | 번역 캐시 (length:hash) | `api/translate.ts` |
| `anime:` | fetchAnimeById L2 | `api/anilist/detail.ts` |
| `otaku:prefs` | UserPrefs | `storage.ts` |
| `otaku:swipes` | SwipeRecord[] | `storage.ts` |
| `otaku:pendingWrites` | 배치 큐 | `storage.ts` |
| `otaku:syncMeta` | 마지막 서버 동기화 시각 | `storage.ts` |
| `otaku:searchHistory` | 검색 히스토리 | `ExploreTab.tsx` |
| `otaku:deviceId` | 디바이스 ID | `storage.ts` |
| `otaku:meCache` | apiMe 결과 1h | `api/otakuApi.ts` |
| `deepl:quota` | DeepL 월 사용량 | `api/translate.ts` |
| `otaku_jwt` (SecureStore) | JWT 토큰 | `api/otakuApi.ts` |

4. UI 컴포넌트에서 사용
5. (백엔드 동기화 필요하면) 백엔드 ADR 추가 + DTO/repo 변경
