## ADR-015. 백엔드 서비스 종료, 클라이언트는 로컬-only

**시점**: 2026-04
**문제**: Railway Hobby 플랜 + PostgreSQL add-on 고정 비용 (~$5–10/월). 사용자 수 적음.
**옵션**:
- A. 그대로 유지 ($5–10/월)
- B. Supabase 등 무료 인프라로 마이그레이션 (4–6h 작업)
- C. 백엔드 종료, 클라는 로컬-only 모드 유지
- D. 앱 완전 종료
**결정**: C. 백엔드만 종료, 클라이언트는 본인용으로 계속.
**근거**:
- 비로그인 모드가 이미 모든 핵심 기능 동작 → 추가 작업 최소
- 데이터 가치 평가: 좋아요 다시 모으면 됨 (백업 X)
- B로 가도 본인 외 사용자 없으면 무의미
- 외부 API(AniList/라프텔/번역)는 그대로라 앱 자체 가치 보존
**구현**:
- `App.tsx` + `src/storage.ts`에 `BACKEND_ENABLED = false`
- auth 단계 자동 스킵, 메뉴 로그인 버튼 숨김
- 헤더 헬스 배지 비활성
- 백엔드 호출 코드는 보존 (Supabase 이전 가능성 대비)

## ADR-014. HomeTab trending+seasonal 단일 GraphQL alias 쿼리

**시점**: 2026-04
**문제**: trending/seasonal을 Promise.all로 병렬 호출 (2 RTT)
**옵션**:
- A. 그대로 (2 RTT, 서버 부담 적음)
- B. GraphQL alias 단일 쿼리 (1 RTT, 서버 처리 약간 무거움)
**결정**: B
**근거**: 모바일 RTT 절약 효과 + 코드 정리 (단일 SWR 키). 측정상 단일=750ms, 병렬=610ms로 단일이 약간 느리지만 대역폭/연결 측면 이득. 큰 차이 아니라 가역적.

## ADR-013. SWR 캐시 의미를 translated → raw English로 전환

**시점**: 2026-04
**문제**: SWR fetcher가 `fetchTrending().then(translateAnimeList)`라 fresh path도 번역 끝나야 swap
**결정**: SWR은 raw English Anime[] 캐시. 번역은 cached/fresh 양쪽에서 `translateAnimeList`로 백그라운드 swap
**근거**: render-then-translate 패턴 적용 가능. 첫 부팅 cold 시 빈 화면 ~500ms 단축.
**비용**: 캐시 prefix `swr:` → `swr2:` bump로 옛 캐시 자동 무효화 (1회 cold load)

## ADR-012. fetchAnimeById 2-tier 캐시 (L1 메모리 + L2 영구)

**시점**: 2026-04
**문제**: 디테일 모달 두 번째 진입 시 매번 AniList 호출 (~700ms)
**옵션**:
- A. L1만 (5분 LRU) — 같은 세션엔 즉시지만 재부팅 시 cold
- B. L1 + L2 영구 — 재부팅 후에도 즉시
**결정**: B. AsyncStorage `anime:` prefix, 24시간 TTL. L2 hit 시 즉시 표시 + fire-and-forget refresh.
**근거**: 디테일 메타는 거의 안 바뀜 (description/studios/genres). 24h 정도면 신선도 충분.

---

## ADR-011. 영어 우선 렌더 + 백그라운드 번역 swap (render-then-translate)

**시점**: 2026-04
**문제**: AniList 응답 → 번역 → 렌더 순차 패턴이라 빈 화면 1.2–2s
**결정**: AniList 응답 즉시 setResults(영어) → translateAnimeList 백그라운드 → id 매칭 swap
**근거**: synonyms 한국명은 mapAnime에서 이미 한국어. 그 외만 영어→한국어 swap이라 flicker 적음.
**테스트**: 측정상 빈 화면 ~500ms 단축

## ADR-010. ANIME_FIELDS 슬림 fragment 분리

**시점**: 2026-04
**문제**: 카드 리스트도 description/studios/banner/source 다 받음 → 응답 35KB
**결정**: `ANIME_FIELDS_LIST` 슬림(18KB) + `ANIME_FIELDS` 풀. discovery/search/recommendations는 슬림, fetchAnimeById만 풀.
**근거**: 응답 50% ↓, 모바일 파싱 시간 감소, AniList 복잡도 rate limit 여유.
**비용**: mapAnime이 옵셔널 필드 폴백 처리 (`studios?.nodes ?? []`)

## ADR-009. Railway 비용 절감 — keepalive/health 조건부 + TTL + swipe 배치

**시점**: 2026-04
**문제**: 비로그인도 health 30초 polling으로 시간당 120 호출. swipe 1번에 1 POST.
**결정**:
- `useBackendHealth(enabled)` — 로그인 시만 polling, 30s → 60s
- `apiHealth` keepalive — 토큰 있을 때만
- `apiMe` 1h AsyncStorage 캐시
- `loadPrefs`/`loadSwipes` 5분 TTL (`syncMeta`)
- swipe 큐 + 3s debounce + bulk POST (`/swipes/bulk` → 폴백 개별)
**근거**: Railway는 호출 수 + egress 기반 과금. 비로그인 사용자가 백엔드 호출 0이 되는 게 큼.

## ADR-008. JWT를 expo-secure-store로 (AsyncStorage 대신)

**시점**: 2026-04
**문제**: AsyncStorage는 평문 파일 → 디바이스 백업/탈옥 시 토큰 노출
**결정**: `expo-secure-store` (iOS Keychain / Android Keystore). 옛 AsyncStorage 키는 첫 `getToken` 시 자동 마이그레이션.
**비용**: 네이티브 모듈이라 풀빌드 필요. 한 번 위험: 풀빌드 안 한 dev client에선 import 시 크래시 → 한 번 잘못 push해서 빌드 직전까지 AsyncStorage로 임시 복귀했다가 풀빌드 후 복원.

## ADR-007. AniList synonyms에서 한국 출시명 우선

**시점**: 2026-04
**문제**: 영어 제목 "Frieren" → Google 번역 → "장례식의 프리렌" (실제 출시명은 "장송의 프리렌")
**결정**: `mapAnime`에서 `pickKoreanTitle(synonyms)` — 한글 비율 가장 높은 항목 사용. 라프텔 매칭 결과로 보강.
**근거**: AniList synonyms엔 인기작 거의 다 한국 공식 출시명 있음. 기계 번역보다 정확.

## ADR-006. AniList 에러 통일 throw + Toast 알림

**시점**: 2026-04
**문제**: 네트워크/HTTP/GraphQL 에러가 곳곳에서 다른 형태로 처리
**결정**: `AniListError` 클래스 + `query<T>()` 래퍼가 모두 throw. UI는 `useToast` + `<Toast>`로 알림.
**근거**: 단일 catch로 통일된 사용자 경험. 429/5xx 등 분기는 메시지에 반영.

## ADR-005. AniList client 동시성 5개 제한

**시점**: 2026-04
**문제**: HomeTab + 디테일 모달 + 검색 동시 polling 시 burst 429
**결정**: client에 in-flight 큐 (max 5). 6번째는 대기.
**근거**: 90 req/min/IP 한도 방어. 큐 오버헤드 미미.

## ADR-003. 시리즈 보는 순서 그룹화

**시점**: 2026-04
**문제**: AniList relations는 PARENT/PREQUEL/SEQUEL/SIDE_STORY 등 다양하게 섞여서 시청 순서 파악 어려움
**결정**:
- main story 4종(PARENT/PREQUEL/SIDE_STORY/SEQUEL)은 한 그룹 → 연도 ASC로 시청 순서
- 나머지(SPIN_OFF/ALTERNATIVE/SUMMARY)는 각 타입별 그룹 → 끝에
- 그룹 사이 디바이더로 시각 구분
**위치**: `src/utils/seriesGroup.ts`

## ADR-002. 라프텔 매칭으로 한국 시청 가능성 보강

**시점**: 2026-04
**문제**: AniList externalLinks는 글로벌 — 한국에서 정말 볼 수 있는지 부정확
**결정**: 라프텔 search API 호출 → 한국어 키워드(번역)로 매칭 → 가장 정확한 KR 카탈로그 prepend. AniList 글로벌은 `regional` 플래그로 구분.
**근거**: 라프텔 자체는 한국 라이선스 정확. 단, 매칭 fuzzy라 100% 보장은 아님.

## ADR-001. 백엔드 분리 (otaku-feed-api)

**시점**: 2026-03 이전
**결정**: 카탈로그(AniList)는 외부 무료 → 백엔드는 인증 + 동기화만 담당. Spring Boot + Kotlin + PostgreSQL + Railway.
**근거**: 직접 구축 시 복잡도/비용 폭증. 외부 API에 의존하는 BFF 패턴.
