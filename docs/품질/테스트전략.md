## 도구

- **Node native test runner** + `--experimental-strip-types` (Node 22.6+)
- **외부 의존성 없음** (jest/vitest 미도입)
- **msw** — AniList client 통합 테스트 mocking
- **GitHub Actions** — push/PR마다 `tsc --noEmit + npm test`

## 명령어

```bash
npm test          # 모든 *.test.ts
npm run typecheck # tsc --noEmit
```

## 새 테스트 추가 가이드

### unit (순수 함수)
1. `*.test.ts` 옆에 두기 (같은 디렉토리)
2. `node:test` + `node:assert` 사용
3. import 경로는 `.ts` 확장자 명시 (native ESM)
4. 실행: `npm test`

```ts
import { test } from 'node:test'
import { strict as assert } from 'node:assert'
import { something } from './some.ts'

test('label', () => {
  assert.equal(something(input), expected)
})
```

### integration (외부 API mock)
msw로 fetch interceptor 설치. setup file은 `src/testSetup.ts` (있으면).

```ts
import { setupServer } from 'msw/node'
import { http, HttpResponse } from 'msw'

const server = setupServer(
  http.post('https://graphql.anilist.co', () => {
    return HttpResponse.json({ data: { ... } })
  }),
)
```

## CI

`.github/workflows/ci.yml`:
- push → main / PR
- Node 22 + `npm ci` + `npm run typecheck` + `npm test`
- 실패 시 PR 머지 차단 권장 (GitHub branch protection)

## 커버리지

현재 측정 안 함 (소형 프로젝트). 우선순위:
1. mappers (외부 API 응답 처리) — 99%
2. swr/translate (캐시 로직) — 90%
3. utils — 100%
4. components — 0% (필요 시 RN Testing Library 도입)
5. tabs — 0% (E2E로 대체)

## 인수 기준 작성 패턴

```markdown
### F2-3. 큐 5개 이하면 자동 prefetch

**Given** 스와이프 큐에 카드 4장 남음
**When** 사용자가 1장 더 swipe
**Then** 큐가 3장 될 때 백그라운드에서 다음 페이지 fetch
**And** 사용자에겐 끊김 없이 연속 카드 표시
```
